# 从主板到设备树：一台计算机的硬件是怎么连起来的

> 学嵌入式 Linux 时，启动日志里会出现 `ttyAMA0 at MMIO 0x9000000`、`PCI 0000:00:01.0`、`GICv2m` 这些词。它们背后其实是计算机组成原理里那套东西：总线、地址空间、中断、存储器层次。这篇把一台真实电脑的硬件结构画清楚，再对应到虚拟机和设备树上。

## 一、冯·诺依曼的五个部件

```text
输入设备   → 键盘、鼠标、麦克风
存储器     → 内存、硬盘、SSD
运算器     → CPU 里做加减乘除的部分
控制器     → CPU 里指挥"下一步做什么"的部分
输出设备   → 显示器、音箱、打印机
```

现代 CPU 把运算器和控制器封装在一起，统称 **CPU（中央处理器）**。

### 三个关键结构

**1. 内存离 CPU 最近**

CPU 内部集成了内存控制器，内存条直接连 CPU，速度最快（几十 GB/s 量级）。

**2. 显卡和高性能 SSD 直连 CPU**

走 PCIe 通道，延迟低于经过芯片组的设备。

**3. 其余外设挂在芯片组下面**

USB、SATA、板载网卡、声卡通过 DMI 链路与 CPU 通信。

这就是**总线分层**：高速设备短路径，低速设备共享一条汇总通道。

## 三、CPU 和所有设备靠三样东西通信

### ① 内存映射 I/O（MMIO）

CPU 访问设备的方式和访问内存完全一样：往某个地址写数据。

```text
CPU 执行：向 0x9000000 写入 'A'
  ↓
地址总线送到串口控制器
  ↓
串口把 'A' 发出去
```

设备的寄存器就"映射"在一段地址上，所以叫 Memory-Mapped I/O。

### ② 中断

CPU 不可能一直轮询每个设备。设备有事时才发出中断信号：

```text
设备拉中断线
  ↓
中断控制器（真实电脑是 APIC，ARM 平台是 GIC）
  ↓
CPU 暂停当前任务，进入中断处理
  ↓
驱动处理完后返回
```

### ③ DMA

大块数据传输不经过 CPU：

```text
CPU 告诉磁盘："把数据写到内存 0x5f000000"
磁盘自己写内存
写完发中断通知 CPU
```

## 四、地址空间：所有设备都是"一段地址"

在一台真实电脑上，物理地址空间大致这样划分：

```text
0x00000000 - 0x7FFFFFFF    内存
0x80000000 - 0x9FFFFFFF    PCIe 设备窗口
0xA0000000 - 0xAFFFFFFF    其他 MMIO 设备
0xFEE00000                 本地 APIC
0xFEC00000                 中断控制器
```

CPU 做一次内存访问，地址落在哪个区间，就由对应的控制器处理。

## 五、存储器层次

"存储"不是一层，而是一串速度与容量不同的层级：

| 层级 | 典型容量 | 典型延迟 |
|---|---|---|
| 寄存器 | 几十字节 | < 1 ns |
| L1 缓存 | 64 KB | 1 ns |
| L2 缓存 | 512 KB | 4 ns |
| L3 缓存 | 16–32 MB | 15 ns |
| DDR5 内存 | 16–64 GB | 80 ns |
| NVMe SSD | 500 GB–4 TB | 50 µs |
| 机械硬盘 | 1–20 TB | 10 ms |

越靠近 CPU 越快越贵越小。程序性能优化的大部分工作，就是让数据尽量留在靠上的层级。

## 六、开机时发生了什么

```text
按下电源
  ↓
CPU 从固定地址读取主板 SPI Flash 中的 UEFI 固件
  ↓
UEFI 自检：探测 CPU、内存、PCIe 设备
  ↓
按启动顺序找到可启动设备
  ↓
加载操作系统内核
  ↓
内核接管：初始化驱动、挂载根文件系统
```

## 七、映射到 QEMU 虚拟机

我们在 QEMU 里搭的 ARM64 虚拟板，结构与真机一一对应：

| 真实电脑 | QEMU 虚拟机 |
|---|---|
| CPU 芯片 | 模拟的 Cortex-A72 |
| 内存条 | QEMU 进程分配的内存 |
| 主板与芯片组 | `virt` 机型 |
| 串口调试口 | `ttyAMA0` |
| PCIe 显卡/网卡 | virtio-blk、virtio-net |
| UEFI 固件 | `edk2-aarch64-code.fd` |
| 硬盘 | `rootfs.ext4` 镜像文件 |

虚拟机里的设备树，就是对这块板子的"硬件清单"：

```text
CPU      → cpus/cpu@0、cpu@1
内存     → memory@40000000
中断控制 → intc@8000000（GIC）
串口     → pl011@9000000
RTC      → pl031@9010000
PCIe 桥  → pcie@10000000
磁盘     → 不在设备树里，由 PCI 枚举发现
网卡     → 不在设备树里，由 PCI 枚举发现
```

设备树里一个节点长这样：

```dts
pl011@9000000 {
    reg = <0x00 0x9000000 0x00 0x1000>;
    compatible = "arm,pl011", "arm,primecell";
    interrupts = <0x00 0x01 0x04>;
};
```

三个属性分别回答三个问题：

| 属性 | 回答的问题 | 对应本文的哪个概念 |
|---|---|---|
| `compatible` | 这是什么型号的设备 | 驱动匹配 |
| `reg` | 它占用哪段地址 | 内存映射 I/O |
| `interrupts` | 它用哪根中断线 | 中断 |

## 八、启动日志与硬件结构对照

```text
9000000.pl011: ttyAMA0 at MMIO 0x9000000 (irq = 13) is a PL011 rev1
```

串口被驱动认领，地址与设备树一致。日志中的 `irq = 13` 是 Linux 中断子系统动态分配的虚拟中断号，和设备树里写的 SPI 编号不是同一套编号。

```text
pci 0000:00:01.0: [1af4:1001] virtio_blk  → /dev/vda
pci 0000:00:02.0: [1af4:1000] virtio_net  → eth0
```

这两块设备插在 PCIe 桥上，由内核扫描总线配置空间发现，所以设备树里没有它们。

## 九、小结

```text
设备树   告诉我们：有什么设备、在哪、怎么通知
驱动     告诉我们：怎么操作这种设备
设备文件 告诉我们：程序从哪里访问它
```

一台计算机的硬件连接，本质上就是三件事：

1. **地址**：设备占一段物理地址，CPU 用读写内存的方式访问它
2. **中断**：设备有事时通过中断控制器通知 CPU
3. **总线分层**：高速设备直连 CPU，低速外设挂在芯片组后面

理解了这三件事，再看启动日志和设备树，就不再是一串看不懂的十六进制数字了。
